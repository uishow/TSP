0. 总体结论

本轮针对您反馈的 4 张截图，已在本机真实运行环境（容器 tsp-local 监听 127.0.0.1:3018、桥接 127.0.0.1:7818）重新逐项验证，结论如下：

  • 图1 / 图4（股票名称缺失）：根因已定位并端到端修复。原 instruments.parquet 的 name 列整列等于代码本身（如 000157.SZ→"000157"），导致全站不显示中文名。已用 eltdx 权威代码表回填 5494/5510 只，修复后经实跑接口验证返回真名。
  • 图3（eltdx「没了」）：为误读。eltdx 3.3.3 已安装并注册在 local_quant 插件内（available:true），并非「没了」。当前 live.connected=false 仅因非交易时段、无实时会话，交易时段会重新连上。UI 无独立 eltdx 开关，它被并入「本地量化数据」。
  • 图2（异动监控全空）：根因明确——runtime/fuyao.env 有 key，但 data-local/data_sources/ 目录为空、fuyao 未被注册为数据源，竞价异动页因此报「竞价数据源未配置」并空表。此项尚未跑通，属「未验证」。
  • 图1 的来源端口 8018：那是升级前的旧实例，现已下线（当前探测返回 502）。当前唯一在跑的是 3018。这是「此前测试没测到 UI」的佐证之一。

3. 图1 / 图4：财务概况 / 全站股票名称缺失

状态：已端到端实测 · 已修复

3.1 根因

data-local/instruments/instruments.parquet 的 name 列整列等于代码本身（如 000157.SZ→"000157"、600519.SH→"600519"）。股票名称解析链 api/ext_data.py:_with_instrument_name() 用该 parquet 做 symbol→name 左连接，因 name 缺失，财务概况、K 线、自选等所有消费名称的页面均显示代码或不显示。

3.2 修复（已落盘）

  • 新增 scripts/fix_instrument_names.py：用 eltdx TdxClient.codes.a_shares(market) 取权威中文名，构造完整 symbol（代码.交易所）为 key 的映射，回填 parquet。注意用 a_shares(m) 取 SecurityCode 对象，而非 all_a_shares()（返回字符串）。
  • 修正 bridge/local_store.py：新增 _eltdx_name_map()（按日缓存 symbol→name）与 _apply_real_names()，对「旧 name 为空/等于代码/纯数字≤6位」的行用真名覆盖，避免 SH/SZ 同号串味（如 000001.SZ→平安银行 而非上证指数）。
  • 重启容器刷新 _instruments_cache 后，运行接口实测返回真名。

3.3 实测证据

curl -s -X POST http://127.0.0.1:3018/api/kline/instruments/names \
  -H 'Content-Type: application/json' \
  -d '["000157.SZ","300237.SZ","600031.SH","600519.SH","000001.SZ","000004.SZ","159915.SZ","000001.SH"]'

→ {"names":{
     "000001.SZ":"平安银行",   "000004.SZ":"000004",
     "000157.SZ":"中联重科",   "300237.SZ":"美晨科技",
     "600031.SH":"三一重工",   "600519.SH":"贵州茅台",
     "159915.SZ":"159915",     "000001.SH":"000001"}}

✓ 普通股票全部命中真名；000001.SZ 正确解析为「平安银行」（证明 SH/SZ 串味已修复）。

⚠ 残留 000004.SZ / 159915.SZ / 000001.SH 等 16 只（多为指数/ETF）eltdx 未提供名称，按「诚实回落代码」保留——这是预期内的边界，不伪造名称。

curl -s "http://127.0.0.1:3018/api/kline/daily?symbol=000157.SZ&limit=1"
→ {"symbol":"000157.SZ","asset_type":"stock","name":"中联重科","rows":[...],"source":"..."}

✓ K 线接口 name 字段也返回「中联重科」，证明修复是 systemic 的，财务概况等页面同源消费后会正常显示。

4. 图3：已配 eltdx 数据源，为什么却说「没了」

状态：已端到端实测 · 属误读

4.1 真相

eltdx 没有「没了」。它在 TSP 里不是独立插件，而是捆绑在 local_quant 插件内。主程序 /api/settings/data-sources 与桥接 /status 都确认其在线：

GET /api/settings/data-sources
→ plugins: [{ "name":"local_quant",
              "display_name":"本地量化数据 / 通达信 / eltdx",
              "available":true,
              "datasets":["daily","adj_factor","minute","full_minute",
                          "realtime","depth5","financial"],
              "status":"本地只读桥接已连接" }]
GET /status (bridge, Bearer)
→ live.version = "3.3.3"
   live.installed = true
   live.connected = false
   local.provider = "local_quant"
   local.tdx_vipdoc_exists = true
   local.tdx_export_exists = true

4.2 为什么会「看起来没了」

  • UI 无独立 eltdx 开关：它藏在「本地量化数据 / 通达信 / eltdx」这一项里，您之前可能找独立的 eltdx 开关而没找到。
  • live.connected=false 是时段现象：当前是非交易时段，eltdx 的实时行情会话未建立，故状态显示「未连接」。交易时段会自动连上，不是故障。

✓ 结论：eltdx 3.3.3 已安装、已注册、可用；「没了」为误读。但实时连接需在交易时段才能 true —— 此为诚实边界，未伪造「已连」。

5. 图2：异动监控数据全空（竞价数据源未配置）

状态：未验证 / 未跑通

5.1 根因

  • runtime/fuyao.env 存在且含 FUYAO_API_KEY（key 在位）。
  • 但 data-local/data_sources/ 目录为空——fuyao 从未被注册为数据源，因此「竞价异动 / 异动监控」页读到的是「竞价数据源未配置」，整页数据为空。
ls -la data-local/data_sources/
→ total 0   (EMPTY —— fuyao 未注册)

5.2 当前判定

✗ 该项未端到端跑通。仅静态确认了根因（key 在、注册缺失），但竞价异动功能本身仍不可用，不能声明完成。

修复路径（列入下一步，不在本报告冒领）：在 data-local/data_sources/ 按上游期望的 schema 注册 fuyao 配置，重启后验证竞价异动页返回真实数据。需先确认上游对该数据源的字段契约，避免再次「配了却不生效」。
