3五步执行过程（点哪里 → 会发生什么 → 结果在哪看 → 出错怎么查）

第 1 步 · 备份漂移态快照
命令：cp ~/Library/Group\ Containers/group.com.docker/settings-store.json backups/docker-settings-store_20261109_1207_before_restore.json
会发生什么：把当前 20506 的配置留档，供回滚。
结果在哪看：ls -l backups/… 显示 585 B。
出错怎么查：路径含空格必须加引号；文件不存在说明 Docker Desktop 配置目录变了。
第 2 步 · 按不可颠倒的顺序改内存
命令链：docker desktop stop → 写 MemoryMiB=40960 → docker desktop start
会发生什么：Docker 引擎关闭 → 配置写入 → 引擎带着新上限启动；顺序反了会被运行中的 Desktop 用旧值覆盖。
结果在哪看：docker info --format '{{.MemTotal}}' = 41986306048；再读 settings-store 仍为 40960（证明没被覆盖）。
出错怎么查：若 docker desktop 命令不存在，说明 CLI 插件未装；若 start 后 docker info 暂不可用，等引擎初始化完再查，不要反复执行 stop/start。
第 3 步 · 等容器恢复并核对补丁
会发生什么：tsp-local 自动重建，先 health: starting，随后 enriched 缓存重算、矩阵预热、启动完整性检查。
结果在哪看：/health → 200 / 0.3.31 / local_only；docker logs tsp-local | grep -E 'ACTIVE|ATTACHED|SKIPPED|DISABLED' 在 12:08:02 重新出现 ENRICHED_INTEGRITY_ACTIVE、BOARD_TAXONOMY_BINDINGS_ACTIVE、MULTI_ASSET_PATCH_ATTACHED。
出错怎么查：启动期 HTTP 000 是正常暂态（healthcheck start_period=180s）；若 3 分钟后仍 000，看日志里 DuckDB 视图注册是否卡在小文件上。
第 4 步 · 还原页面真实请求
怎么做的：从上次证据链 data-local/backtest_runs/9de075c4ca.json 的 config 取全部参数， 再用 /openapi.json 核对 GET /api/backtest/strategy/stream 的参数名，生成 1525 字符 URL。
关键：不带 symbols（→ 全市场 5510 只）、不带 force（→ 页面真实路径）、带全部 overrides。
出错怎么查：只验证 POST 带少量标的不能证明页面能跑；stock,etf 这类多值 asset_type 是非法值。
第 5 步 · 跑两次并核对三层
命令：curl -sS -N --max-time 600 -H 'Accept: text/event-stream' "$URL" -o /tmp/stream2020_restore_page.sse， 第二次在 URL 末尾加 &force=1。
结果在哪看：两份 SSE 文件（各约 1.49 MB）、data-local/backtest_runs/{run_id}.json（各 17,954 B）、docker logs。
出错怎么查：用精确串 exitcode=-9 / worker exited without result / event: error 判断， 别用 '-9' in 全文——pnl_amount:-952.4 这类盈亏负数会误命中。
