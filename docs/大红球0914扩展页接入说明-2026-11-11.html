1 · 这是什么

把本地参考目录 ref-doc/大红花0914分享版_20261110/ 这个多文件静态站点（主页面 zhangge_redboll0914.html + res/ css/ js/ DatePicker/ fzb_cache.js），接入为 TSP 的一个**扩展页**，在 TSP 左侧菜单里叫「大红球0914分享版」。

该工具是一个纯前端页面：由你的浏览器直接联网向东方财富 / 腾讯 / 新浪 / 同花顺的公开行情接口取数、在浏览器里计算画图，不经过 TSP 容器（容器是零外联的）。它本身就是为「浏览器打开 / 嵌入自定义网页」设计的（其自带安装说明已写明）。

2 · 怎么用（点哪里 → 发生什么 → 结果在哪看）

  1. 打开 TSP（http://localhost:3018 或 http://127.0.0.1:3018）。
  2. 第一次请按 Cmd/Ctrl + R 刷新一下扩展页列表（前端菜单有缓存）。
  3. 在扩展页 / 自定义分析菜单里找到「大红球0914分享版」，点开。
  4. 页面打开后：在顶部输入框输入 6 位股票代码，点「查询」或回车 → 出分时、大单球、资金等。
页面里的行情数据由浏览器直连第三方接口。若出现「连接状态异常 / 东财分钟净额（估算，非逐笔）」等提示，是第三方接口跨域或停服导致，与本接入无关（工具安装说明已声明）。

3 · 为什么用「独立端口」而不是 TSP 内部路由

TSP 扩展页用 iframe 嵌入。前端有同源校验 R()：当 iframe 的源和 TSP 网页同源时会拒绝嵌入（提示「不支持嵌入本站」）。此前「挖因子」扩展页就踩过这个坑（写成 https://127.0.0.1:3018/...，https 握手失败 + 同站被拒 → 「响应无效」）。

接法做法是否规避同站坑
独立端口
本次采用		页面跑在宿主侧独立静态服务（绑 127.0.0.1:8909），iframe url 写 http://127.0.0.1:8909/...是。不同端口=不同源，与你怎么访问 TSP（127.0.0.1 或 localhost:3018）都无关
同端口内部路由override 加 /xxx 路由，url 写 http://localhost:3018/xxx是，但依赖你用 127.0.0.1 访问 TSP（localhost 别名绕开）

独立端口更安全且和项目里已有的「大红球系统(8989) / 划线(8865) / 擒龙(8088) / 异动(18765)」外部工具同一类接法，也避免盘中重启 TSP 容器。

5 · 自启与守护

  • 现在：服务已以前台后台任务方式常驻（pid 47881，监听 127.0.0.1:8909）。
  • 重启 Mac 后：~/Library/LaunchAgents/com.tsp.dahq0914.plist 会被 macOS 登录时自动加载（RunAtLoad）；KeepAlive 保证进程崩溃后自动重启。
  • 手动启停（如需）：
    # 启动
.venv/bin/python scripts/dahq0914_server.py &
# 停止（按 pid）
lsof -tiTCP:8909 -sTCP:LISTEN | xargs kill
沙盒环境下 launchctl bootstrap 会报 I/O error（XPC 限制），但 plist 放在 ~/Library/LaunchAgents/ 即可被系统自动加载，无需手动 launchctl。重启 Mac 后才会真正验证一次。

以上均在挂载卷 / 用户目录，不影响 TSP 镜像与升级。
