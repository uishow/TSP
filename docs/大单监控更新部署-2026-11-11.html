2.3 适配器小改（新增 /depth5 + 目录对齐，已提交）

移植包原适配器缺 /depth5，而 sampler 需五档。按 sampler README 明示的「把 fetchDepth 换成任何返回 {bids,asks} 的接口」逃生舱设计，在宿主侧适配器加：

  • bigorder.py 新增 eltdx_depth()：用仓库宿主 .venv 的 eltdx 取真五档；裸码转换（剥 .SH/.SZ）；线程锁；失败一律返回空列表不抛 500。
  • main.py 新增 POST /depth5（asyncio.to_thread 包裹），与适配器同端口 3021。
  • SEAL_DIR 默认改为 PKG_ROOT/sampler/封单；AUCTION_DIR 默认改为 PKG_ROOT/watcher/大单提醒。省去每次启动带环境变量，仍可用 BIGORDER_SEAL_DIR/BIGORDER_AUCTION_DIR 覆盖。

3. 怎么用（点哪里 → 发生什么）

入口TSP 左侧栏「大单监控」（按 F5 刷新后出现 / 更新） 切票页面输入框打代码（如 002639 或 002639.SZ）回车 档位选「500万」等阈值 → 气泡与逐笔表同步过滤（严格 amt >= th，非 th/2） 剔除勾「剔创业板 / 剔科创板」→ 300/301/688 开头消失 在线状态右上角「ELTDX 在线」= 3021 通；「离线」= 3021 没起或端口错 结果在哪看分时图 + 大单气泡（买红卖绿）+ 四档净额 + 量化分析卡 + 全市场主力净额榜 + 封单质量 + 竞价强度
出错怎么查
  • 白屏：F12 看 console；多半 page.json 的 sha256 与 bundle 不符（本次已校验一致）
  • 四档全 0：上游（东财/同花顺）限流，等几秒刷新；或看 /bigorder/flow 报错
  • 买卖全反：有人把逐笔 1=卖 2=买 改回「1=买」（铁律 5.1，勿改）
  • 封单「未采样」：sampler 没起或当日该股不在候选池（需 ≥2 次采样才有质量判定）
  • 竞价「未采集」：不在 09:26–09:30 窗口（窗口外无法回补），或 watcher 没起

4. 启停策略（三服务 · 用户第 6 项指令延伸）

大单监控现在由 三个宿主进程组成，遵循「盘中启用、盘后关闭」策略，不做常驻 launchd 自启（与策略冲突；收盘后自动退出是正确行为）。

服务端口/路径盘中启动收盘行为
适配器3021§2.4 命令手动停
采样器 sampler写 sampler/封单/node seal-sampler.mjs15:05 自动退出
巡检器 watcher写 watcher/大单提醒/node bigorder-watch.mjs --dry15:05 自动退出

交易日用，按上面三条依次启动即可（顺序是 适配器 → 采样器 → 巡检器，巡检器依赖 3021）。三个都起后页面右上变「ELTDX 在线」，封单/竞价接口开始有数据。

本次为验证已手动启动三服务；若要停，结束对应后台进程即可。如需「每天自动起 + 自动采 09:26 竞价」，可后续单独评估加 launchd（当前按用户决策仍不常驻）。

5. 未做部分（明确告知）

按用户纠正后的决策（只不做 QQ 推送，其他还是要做的），本次唯一跳过的是：

  • 巡检器的 QQ 私聊推送：watcher 用 --dry 运行，所有 pushPrivate 被 if(!DRY) 门控跳过；config.json 中 qq.enabled=false 双保险。代码 lib/qq-push.mjs 已随包部署但不会被调用。将来要启用，把 qq.enabled=true 并填 onebotUrl/ownerQQ/token，改以不带 --dry 的方式运行即可，无需改其他代码。

其余（封单采样、连续大单巡检、封单骤降巡检、09:26 竞价强度采集、全部数据接口）均已部署并验证。

6. 升级兼容性（二开铁律）

  • 扩展页在 data-local/ext_pages/（挂载卷，非容器内 /app/app）；适配器 / 采样器 / 巡检器都在 services/bigorder_adapter/（宿主进程，不进镜像）。三者都不触碰镜像、compose.yaml、upstream/。
  • 升级 TSP 镜像后：扩展页与宿主三服务照常挂载/运行，不会阻断启动；按 §8 重跑验证即可。
  • 适配器新增的 /depth5 是「逃生舱」实现：若上游未来原生自带 ELTDX /depth5，关闭本路由（删 main.py 中该路由 + bigorder.eltdx_depth）即可，sampler 改回读上游；不影响其余接口。
  • SEAL_DIR/AUCTION_DIR 默认指 sampler/watcher 子目录，属本仓自有布局，升级 TSP 不触碰。

7. 回滚方法

两种方式任选：

方式 A：本地备份还原（最快，仅扩展页）

cp backups/bigorder_page_20261111/bundle.js.bak_55806_16ae40 \
   data-local/ext_pages/big_order/bundle.js
cp backups/bigorder_page_20261111/page.json.bak_55806_16ae40 \
   data-local/ext_pages/big_order/page.json
# 然后 TSP 里 F5

方式 B：Git 还原

git checkout -- data-local/ext_pages/big_order/bundle.js \
                data-local/ext_pages/big_order/page.json
# 适配器/sampler/watcher 的改动如需回退：git checkout -- services/bigorder_adapter/

回退适配器改动会同时移除 /depth5 与目录对齐默认值；届时若还要 sampler，需手动带 BIGORDER_SEAL_DIR 环境变量启动适配器。
