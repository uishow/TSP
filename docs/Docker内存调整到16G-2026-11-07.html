背景

当前 Docker 给容器分配的内存为 7.747 GiB（docker info → Total Memory 实测）， 全市场股票回测需要把几千只标的 + 11 个月数据一次性装入内存矩阵，内存不足被系统 OOM Killer 强杀（exitcode=-9）。 把上限调到 16 GiB 即可根治。

一、图形界面操作步骤（推荐，最简单）

1
在屏幕右上角（菜单栏）找到 Docker 鲸鱼图标（🐳），点击它。
2
在弹出的菜单里点 “Settings”（部分旧版本叫 “Preferences”，齿轮图标）。
3
左侧栏点 “Resources”（资源），再点右侧的 “Advanced”（高级）标签页。
4
找到 “Memory”（内存）这一项，把滑块拖到 16 GB，或直接点击数字框输入 16。
5
点击右下角 “Apply & Restart”（应用并重启）。Docker 会重启，约 10~30 秒。

二、改完后如何验证（我来跑，你也可自查）

重启完成后，在终端执行：

docker info | grep "Total Memory"

正常应显示 Total Memory: 15.62GiB 左右（16 GB 换算）。若仍是 7.747GiB，说明没保存成功，重做第 4~5 步。

⚠️ 注意：Docker 重启后 TSP 容器也会跟着停，需要重新拉起（一般 docker start tsp-local 即可，或你平时怎么起的就怎么起）。

三、调完之后要做的（回测验证）

步骤操作预期
1确认 TSP 容器已启动并可访问 :3018/health 返回版本
2重跑之前失败的全市场回测（同样的策略 + 区间）不再出现 exitcode=-9
3观察回测 worker 是否 done产出 run_id 与结果

我会在这之后立即帮你重跑那次失败的全市场回测，确认 OOM 消失。如果你只调到 16 GiB 仍偏紧，可同样步骤调到 24 GiB 更稳妥。

为什么是 16 GiB？ 你 Mac 物理内存 48 GiB，留给 Docker 16 GiB 完全宽裕；TSP 基线约 2.3 GiB，全市场回测峰值约需 8~12 GiB，16 GiB 留出安全余量。调太高（如 32 GiB）平时不用也浪费，16~24 GiB 是当前最优区间。

四、备选：直接改配置文件（进阶，非必须）

Docker Desktop 的设置本质是写入配置文件，GUI 改完会自动落盘，普通用户无需手动改文件。若你确实想手动改，位置通常在：

~/Library/Group Containers/group.com.docker/settings.json

其中 "memoryMiB": 16384 即为 16 GiB。改完需完全退出并重启 Docker Desktop 才生效。手动改有写错风险，建议优先用上面的 GUI 步骤。
