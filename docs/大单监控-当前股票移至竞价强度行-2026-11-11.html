2. 点哪里 → 发生什么 → 结果在哪看

打开页面TSP 左侧栏点「大单监控」，按 Cmd/Ctrl+R 强刷一次让新代码生效 看当前股票不看第一行了，看「竞价强度」那一行的最右端；左列被选中的行仍高亮 换股票点左列自选任意一行，或点右栏榜单任意一行 → 「竞价强度」行右端的「当前：」跟着变，右侧所有图表同步刷新 看非自选股点右端「手动输入」→ 搜索框就在这一行就地展开，打代码/名称回车；再点一次收起 结果在哪看「竞价强度」行右端的蓝色「当前：」标签 = 当前票；左列高亮行 = 同一只票；右侧图表 = 这只票的数据
两种正常现象，别当成坏了：① 点「手动输入」展开搜索框后，这一行会被撑高一点； ② 「竞价强度」的提示文字很长，窗口较窄时「当前股票」组会换到下一行单独靠右——这是窄屏自适应，不是错位。

3. 技术实现（为什么功能不丢）

页面是未压缩的原生 ES module，可以直接改。本轮只动了 4 处，全是界面骨架，没有任何取数、切票、降级逻辑改动：

#位置改动
1文件头注释登记 v4.1 变更与原因
2CSS 区新增 .bo-curgroup{margin-left:auto;display:flex;…;text-align:right} 与 @media(max-width:700px) 窄屏规则
3顶栏 bar删掉 3 行 bar.appendChild(...)；curChip / manualBtn / searchWrap 仍在原处创建，只是暂不挂到 DOM
4竞价强度 auc在原有 5 个元素之后 appendChild(curGroup)，把上面三个节点一次性挂进去
/* v4.1：把顶栏那组「当前：名称 代码」+「手动输入」+搜索框挂到本行右端 */
const curGroup = h("div", "bo-curgroup");
curGroup.append(curChip, manualBtn, searchWrap);
auc.appendChild(curGroup);

关键点：移动的是同一批 DOM 节点，不是重建。所以 updateCurChip()（刷新标签文字）、switchSymbol()（切票时改 input.value、收起建议框）、hideSug()（searchWrap.contains 判断）、「手动输入」的点击展开，全部继续引用原来的变量，不需要改一行。这也是本轮回归测试全绿的原因。

数据来源依旧：/api/watchlist 名单、/api/watchlist/groups 分组、:3021/bigorder/snapshot 现价/涨幅；TSP 请求全用同源相对路径，不写死端口。全部未碰镜像 / tag / digest / compose.yaml / upstream/ / 容器内 /app/app /app/static；override 仍 22。
