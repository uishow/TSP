3.3 第三层：数字口径对不对

移植包反复强调的几条「铁律」，本次一条没改（cmp 逐字节一致已证明），这里写下来供以后复核：

规矩为什么 / 现场核对
东财逐笔 1 = 卖，2 = 买，4 = 集合竞价bigorder.py::ticks() 里是 "sell" if bs=="1" else "buy" if bs=="2" else "auction"，正确。文件头部注释还留着旧的「1=买 2=卖」，按移植包附录 B「两处不要改」的要求没有动它，只在这里提示，避免以后有人照注释改反。
大单阈值必须严格 amt >= th不能写成 th/2，否则 500 万档会混进 250 万的单子。页面逻辑原样保留。
同花顺是四档金额汇总，不是逐笔只能看「超大/大/中/小」四类买卖额合计，不能当 L2 逐笔明细用。
两家数据只比方向，不比绝对值分档阈值不同，绝对值直接比会得出错结论。
封单质量判定封单占成交额 <3% 虚板、3~10% 偏弱、>10% 正常；骤降 >30% 且仍涨停 = 撤单嫌疑。
数据源卡片是「零能力」source/bigorder_source.yaml 没有登记，绝不能伪装成 realtime 数据源指过去，否则会把整个实时行情面板弄坏。

4网络状况更正（重要）

此前判断需要更正。研读阶段（08:29 左右）探测 push2.eastmoney.com 和 d.10jqka.com.cn 时，得到的是「DNS 正常、TCP 连上、0 字节、超时、HTTP 000」，当时的结论是「这两个行情网站在当前出口不可用」。08:5x 复测直连，两个网站都正常返回 HTTP 200：
http://d.10jqka.com.cn/v6/realhead/hs_002639/defer/last.js   → HTTP 200  0.13s
https://push2.eastmoney.com/api/qt/stock/details/get?...     → HTTP 200  0.31s

随后页面主接口 /bigorder/flow 立即拿到 ok:true 的真实快照，耗时 0.125s。所以结论改为：上游行情站当前可达，数据链路是通的；先前那次超时属于当时出口/探测路径的临时状况，不是移植包缺陷，也不是 DNS 问题。

对使用的影响：不需要任何「换网络 / 找代理」的前置动作，页面现在就能取数。若以后再碰到全 0 或「ELTDX 离线」，按 §8 三步排查，并注意区分「盘前本来就没数」和「真的连不上」。

5盘前为什么很多是 0

验收时间是 2026-11-10 08:54（开盘前）。这个时刻：

  • 还没有连续竞价成交 → 逐笔成交 0 笔、四档买卖额 0、分时资金流 0 行，全市场榜单的「主力净额」为空。
  • 能取到的是静态信息：股票名称、昨收价、行情时间、市场状态「闭市」。
  • 「封单质量」要有当天的封单采样文件；「竞价强度」只能在 09:25–09:30 采集，窗口外无法回补。这两块本次没装采集器，接口明确返回「未采样 / 未采集」，不是空白报错。
建议：9:30 开盘后（比如 10:00）再进这个页面看一次，四档金额、逐笔表、档位筛选才有实际内容。本次没有替你做这一步，见 §9。
