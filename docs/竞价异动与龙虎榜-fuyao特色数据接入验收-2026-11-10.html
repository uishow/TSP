② 之前为什么是空的（根因，不是页面坏了）

TSP 里这两个页面要走一条特殊通道：程序会先问一句「装了 fuyao 这个数据源吗？」，装了才去取数。而咱们这套本地部署为了零外联，把所有外部数据源都锁掉了，只留本地 local_quant 一个 —— 所以回答永远是「没装」，页面就显示「数据源未配置」。

核查点实测结果三态
修复前两个接口/api/market-recap/dragon-tiger 和 /api/market-recap/auction-benchmark 都返回 {"state":"source_unavailable"}已端到端实测
前端那行字的判断条件镜像内 /app/static/assets/Page-DsMN8rNw.js 只看 D.auctionBenchmark() 返回的 state === "source_unavailable"，不看设置页的数据源列表仅静态核对
为什么不能直接放开 fuyaooverrides/source_policy.py 只允许回环与桥接 7818，并强制所有 provider = local_quant；scripts/verify_tsp.py 里明确断言 fuyao.aicubes.cn 必须被阻断。放开就等于破坏零外联和升级验收已端到端实测
设置页/api/settings/data-sources 的 plugins 只有 local_quant、custom: []已端到端实测
镜像里其实自带 fuyao 插件/app/app/plugins/fuyao/{plugin.yaml,client.py,provider.py} 都在，龙虎榜 / 竞价风向标是「非路由数据集」，由 provider 方法直接调用；只是被策略挡住了仅静态核对
一句话：不是缺功能，是缺一份「本地能读到的真实数据」。所以补的是数据快照 + 一个只认本地文件的只读回答，不是改主数据源。

③ 这次怎么接进来的（三步，全程不碰原系统）

步骤谁在做做了什么
1 拉数你的 Mac（宿主机）scripts/fuyao_recap_sync.py 拿着密钥，向 fuyao 要两类数据：龙虎榜三榜（全部 / 机构 / 游资）+ 竞价短线风向标。用到 X-api-key 请求头。
2 存文件你的 Mac（宿主机）存成普通 JSON，放在 data-local/fuyao/recap/：按接口返回的真实日期命名，另有一份 latest.json 记录「最新是哪天、各天多少行」。文件里没有密钥。
3 只读TSP 容器overrides/fuyao_recap.py 只回答「fuyao 装了吗」和「把 fuyao 给我」这两句话，给出去的是一个只会读本地 JSON 的对象。它不发任何网络请求。

几条硬规矩（都实测过）：

  • 按真实日期存，不按请求日期存。请求 11-10 的龙虎榜时接口返回 0 行（还没发布），脚本不落盘；TSP 自带的回退机制自动改显示 11-09 并标记「上一期」。绝不会拿明天的数据冒充今天，也不会返回一张空表假装「今天没有」。
  • 三榜必须同一天且都有内容才存。避免半套数据。
  • 容器里注册表一行没加。所以设置页依旧只显示 local_quant，主数据源没变，回测 / 行情 / 板块全部走原来的路。
  • 其它名字一律照旧。只有名字恰好是 fuyao 时才走旁路；其它请求原样交回原来的单源策略，该拦的还是拦。
  • 交易日历故意返回空。上游有两个地方会顺带问 fuyao 要交易日历，返回空 = 它们按「不知道」回退到本地近似，跟装补丁之前完全一样，不改主流程口径。

⑦ 密钥边界、升级兼容与回滚

密钥放哪了

  • 只放在本机 runtime/fuyao.env，权限 600；格式 FUYAO_API_KEY=sk-fuya…（本文只写前缀，不写全文）。
  • 没有写进任何文档、日志、Git 跟踪文件；没有写进 .env（它是 compose 的 env_file，会注入容器）；没有写进 data-local/user_data/secrets.json（该目录挂载进容器）。与既有 docs/fuyao-offline.md 的约定一致。
  • 容器里读不到密钥，也不需要读 —— 它只读已经拉好的 JSON。

升级兼容（铁律）

  • 补丁全在挂载卷 overrides/ 与 scripts/，不碰镜像 / tag / digest / compose.yaml / upstream/ / 容器内 /app/app / /app/static。
  • 启动时自动核对补丁目标（custom.is_custom_provider、custom.get_provider、FuyaoError 类）。升级后如果上游函数换了名字或签名 → 记 FUYAO_RECAP_PATCH_SKIPPED 日志并原样退回，TSP 主功能照常可用，最多这两个页面回到「未配置」，绝不白屏、绝不阻断启动。
  • 快照是运行时数据，缺失不会导致补丁失败：记 FUYAO_RECAP_NO_SNAPSHOT，页面照旧显示未配置；补跑一次同步脚本即恢复，不用重启容器。
  • 升级 SOP 加一条核对项：升级后 docker logs --tail 200 tsp-local | grep FUYAO_RECAP，看到 ACTIVE ... ready=True 即正常；看到 SKIPPED 就按上面处理，不要改镜像去「修」。

回滚（三档，任选）

  1. 只关这两个页面：TSP_FUYAO_RECAP=0 重启，其余一切不变。
  2. 删补丁：删掉 overrides/bootstrap.py 末尾追加的那 7 行，重启；两个 .py 留着不生效也无害。
  3. 连数据一起撤：删 data-local/fuyao/recap/，页面回到「未配置」，不报错、不影响别的功能。
