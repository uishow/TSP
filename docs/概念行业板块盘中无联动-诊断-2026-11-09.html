一、一句话结论

不是前端「没做联动」，是板块维度的盘中数据链路断了：概念/行业轮动与「分时走势·等权」都靠全市场分钟 K 分区计算，而今天（2026-11-09 周一）的分钟分区根本没生成，最新只到上周五 11-06 14:55。
实时个股报价是另一条链路（30 秒轮询 → SSE 推送 → 页面重算），它一直在正常跑；两条链路没有打通，于是看到「个股在动、概念/行业板块不动」。
「联动」可能指两件事，本轮都查了：
① 页面之间联动（概念热点 ↔ 对应行业同步高亮）：系统里没有这个设计，两个页面是独立路由、独立数据源配置。
② 盘中随行情实时更新：个股涨幅层会动（靠 SSE 推 market-snapshot），但板块轮动/分时层不会动（靠分钟分区）。你看到的「没联动」主要是②。
本轮零改动：没有改偏好、数据源、代码或行情数据，没有重启服务，无需回滚。第六节给出「要真正联动」的修复路径与风险，等你决定后再动。

三、五层因果链（源码级）

第 1 层 · 板块轮动 API 只能读「最新分钟分区」，且没有 date 参数
app/api/sector_rotation.py:1/29 文档串：「板块切换(盘中轮动) API — 基于全量分钟数据 + 扩展资金流」「盘中板块切换走势：全量分钟K聚合到板块」；端点只接受 kind/flow/top/bucket/...，不接受 date。
# app/services/sector_rotation.py:98
def _latest_minute_partition(minute_dir):
    parts = sorted(d.name[5:] for d in minute_dir.iterdir()
                  if d.is_dir() and d.name.startswith("date=") and (d/"part.parquet").is_file())
    return parts[-1] if parts else None      # ← 固定取最新分区 = 2026-11-06

# :139 _minute_pcts(minute_dir, target) 读 date={target}/part.parquet
第 2 层 · 「板块分时走势·等权」也是同一份分钟分区
app/api/ext_data.py 的 /{config_id}/dimension-intraday 同样 pl.read_parquet(minute_dir / f"date={target}" / "part.parquet", columns=["symbol","datetime","close"])，读失败即返回 status=no_data。前端 DimensionMembersDialogContent 里这个查询虽有 refetchInterval:60s，但底层分区不变，刷新也是旧数据。
第 3 层 · 前端把这种状态明确标成「回放」，并关掉盘中指数分钟曲线 
// SectorRotationCard-B65z-2K_.js
C = useMemo(() => {
  if (!o || o.status !== "ok" || !o.date) return "replay";
  const {date: t} = Dt();                       // 今天
  return o.date !== t ? "replay" : _t() ? "live" : "replay";
}, [o]);
// o.date = 2026-11-06 ≠ 今天 → C = "replay"（灰标「回放 · 2026-11-06」）

// 指数分钟查询：C 不是 live 时直接不请求
enabled: !!(o?.date) && C === "live", refetchInterval: 3e4

// 轮动查询：盘中 30s 自动刷新，但拉回的仍是 11-06 的旧 date
refetchInterval: () => _t() ? 3e4 : 3e5, staleTime: 25e3
所以「30 秒自动刷新」是有的，但刷新的是同一个旧分区——看起来就像完全不联动。
第 4 层 · 实时行情走的是另一条链路，且采集范围不含板块指数 
QuoteService (30s) → SSE /api/intraday/stream 事件 "quotes_updated"
  → Layout 收到后 invalidateQueries(白名单前缀)
  → 白名单 oE = ["watchlist-quotes","watchlist-enriched","quote-status",
                 "index-quotes","overview-market","limit-ladder","market-snapshot"]
  → 概念页/行业页的 marketSnapshot 重新拉取
概念页 Page-C2Dy6nvm.js / 行业页 Page-Bj4x-mi6.js 用 He(marketSnapshot.rows) 建 symbol→行情 Map，再由 We(group, map) 在浏览器端按 change_pct/turnover_rate/amount 聚合出板块涨幅。两页 refetchInterval 均为 0 处，只有 staleTime:6e4 + 右上角手动「刷新」按钮，完全依赖全局 SSE 推送。
注意：intraday/status 里 index_symbol_count=9、etf_symbol_count=0，实时采集的是 5034 只个股/指数报价，没有概念或行业板块指数，所以「板块涨幅」只能靠成分股聚合，不能像指数那样直接取实时值。
第 5 层 · 分类归属本来就是静态快照，且两页彼此独立
ext_gn_ths（扩展概念）与 ext_hy_ths（扩展行业）的 mode=snapshot，描述明确写「无网络拉取、无拉取调度」「仅有当期成分归属，不提供历史成分变更，PIT 成分数据未验证」；extDataRows 的 queryKey 也不在 SSE 实时刷新白名单里。概念页 /concept-analysis 与行业页 /industry-analysis 各自有独立 configId、dimensionField 与「配置数据源」按钮，前端没有跨页联动逻辑。
结论：分类归属盘中不变是设计使然；真正该随行情变的是「板块涨幅/轮动/分时」，而其中轮动与分时被分钟分区卡死。

开关、能力门控、交易时段、限流闸门全部通过（日志 09:39~09:43 反复出现 custom source 'local_quant' provides dataset 'full_minute': granted intraday.universe），但全天修复轮拉回空数据，rounds=0 / last_rows=0，因此今天的 kline_minute/date=2026-11-09 压根没被创建。

为什么拉回空数据

  • app/services/minute_refresh.py 设计说明：数据源需实现 get_intraday_batch(symbols)（全天修复轮）与 get_intraday_latest(count)（廉价稳态增量轮）。只有修复轮的源会被标 repair_only=true，节奏下限抬到 60s。
  • 当前 full_minute_data_provider=local_quant 虽声明 full_minute 数据集并拿到 intraday.universe 能力，但修复轮调用返回空 → last_error="intraday full returned no data"。本地桥接提供的是实时报价快照（5034 只），不是全市场分钟 K 序列。
  • minute_sync_enabled=false：盘后分钟同步也关着；11-06 的盘后管道结果 minute_rows=0，所以连历史分钟分区也只到 11-06 且不是靠管道补的。
  • 附带问题：今天 09:38 的日线任务因「本地数据源 daily 不可用」失败，但 /api/data/status 显示 daily.latest_date=2026-11-09，说明当日日线由实时 flush 路径写入；这条路径不写分钟分区。
一句话：实时报价（秒级）与分钟 K（序列）是两套数据能力。当前本地源只有前者可用、后者返回空，所以所有「按分钟聚合成板块」的功能盘中都不动。

五、页面怎么点（现在能看到什么 / 怎么手动刷新）

① 概念板块页 / 行业板块页
点哪里：左侧导航「概念板块」或「行业板块」→ 页面右上角有「刷新」圆形箭头按钮（旁边是「配置数据源」齿轮）。
会发生什么：前端同时 extDataRows.refetch() + marketSnapshot.refetch()，用最新个股报价重算板块涨幅。
结果在哪看：标题下方副标题会显示 as_of · N 个概念/行业 · M 只标的；板块列表的涨幅、涨跌家数、活跃分会更新。
出错怎么查：若一直不变，看「设置 → 数据源」里实时刷新相关开关（Layout 的 SSE invalidate 白名单受用户开关控制）；或按第八节命令直接看 market-snapshot 的 as_of 与涨幅分布。
② 板块轮动卡片（「盘中轮动」）
结果在哪看：卡片右上角现在是灰色「回放 · 2026-11-06」，不是绿色「盘中」；副标题显示 2026-11-06 14:55 · 切换强度…。
会不会自动变：盘中每 30 秒确实会重新请求，但只要今天分钟分区不出现，就一直显示回放。点刷新也不会变，这不是前端卡顿。
③ 板块分时走势（点开成分弹窗时）
「分时走势 · 等权」每 60 秒轮询一次，底层同样读 date=2026-11-06/part.parquet，所以曲线是上周五的形态。

六、要真正联动需要做什么（建议，本轮未执行）

先说清楚：前端已经有轮询、SSE、绿点判定、等权分时等完整逻辑，缺的是数据。改前端解决不了；要让联动真正生效，必须让 kline_minute/date=2026-11-09 在盘中持续被写入。
  1. 补齐本地源的分钟能力（治本）：让 local_quant 插件/宿主桥接实现 get_intraday_batch(symbols)，能从本机「本地量化数据」的分钟线返回当日全市场分钟 K；最好再实现 get_intraday_latest(count) 以解除 repair_only，把节奏从 ≥60s 降到 6s。推荐方向，但需要改插件/桥接代码并重新验证。
  2. 换用支持全量分钟的数据源：minute_refresh.py 说明 TickFlow Expert 档提供 intraday.batch + intraday.universe；或接入声明 full_minute 且实现增量端点的自定义源。需要对应档位/凭据，且会引入外部依赖。
  3. 手动补当日分钟：POST /api/kline/sync_minute 或 /api/kline/sync_minute_single 存在，但受 KLINE_MINUTE_BATCH 能力门控，且 minute_sync_enabled=false。本轮未验证，不建议在盘中盲试（可能写坏当日分区）。
  4. 打开盘后分钟同步：minute_sync_enabled=true 只能补历史/盘后，不能解决盘中联动；且 11-06 管道 minute_rows=0，需先确认数据源可用。
容量与风险：全市场 5510 只 × 每日约 240 根分钟 K，单日就是百万行量级；持续写入会显著增加磁盘与 parquet 小文件，按本项目既有踩坑，任何分钟分区写入后都要注意 compact 与 DuckDB 视图刷新。本轮未改任何配置，以上均待你确认后再做。

七、常见误解

  1. 「页面坏了 / 前端没做联动」：前端 30s/60s 轮询、SSE 推送、盘中/回放判定都在，只是数据停在上周五。
  2. 「概念涨了行业就该跟着动」：两页是独立路由、独立 configId，没有跨维度映射联动的设计；且概念与行业分类来自不同表（ext_gn_ths / ext_hy_ths，申万 vs 同花顺体系）。
  3. 「板块分类没同步」：local_* 的 latest_sync_date=2026-11-09 09:38:07，分类归属今天有同步；snapshot 类表本来就是静态归属，盘中不变属正常。
  4. 「日线已有今天，分钟也该有」：日线由实时 flush/盘后管道写入，分钟由独立的 minute_refresh 服务写入，两条链路互不相干。
  5. 「/api/data/status 的 rows:0 说明没数据」：这是上游「零数据扫描」的恒定设计，判断日期范围看 earliest_date/latest_date/trading_days，行数一律以 DuckDB 直查或分区目录为准。
