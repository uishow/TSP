先立一条规矩：HTTP 200 ≠ 功能可用

本机的 86 / 86 只读端点全部返回 HTTP 200（证据 docs/tsp-smoke-20261106-v0331.json，镜像标记 v0.3.31），OpenAPI 快照为 370 paths / 414 operations（/tmp/tsp_openapi_v0331.json）。但这只说明「接口能连上、能返回」，不代表业务功能好用、更不代表我们点过按钮跑通了。本手册严禁把 200 写成「功能可用」，所有本机能力一律按三态标注：

徽章判定标准你可以怎么理解
已端到端实测发起过真实任务、拿到终态、核对过落盘数据与语义「这条链路我们真的跑过并验过结果」
仅静态核对或冒烟只读接口 200、返回有真实数据，或源码/契约静态核对，但没跑完整交互「接口在、数据在，但没点过按钮做完整操作」
未验证从未发起过真实操作「别当成已经能用，出问题先按未验证处理」

文中 上游说明 引自 data-local/upstream_docs/ 里的原始文档（会标出文件名），那是软件设计上应该有什么；凡带三态徽章的，才是本机部署实际测到什么程度。两者不能混为一谈。

每日盘后更新数据（让面板跟上今天收盘）

已端到端实测
目标：把本机通达信 vipdoc 里今天的收盘数据，灌进 TSP 并重新算好指标。你可以把它想成「每天关市后给面板做一次全量刷新」——不做这一步，后面的出票、回测、监控用的都是旧数据。

①点哪里（页面与按钮）

  1. 先备料（在本机，不在面板里）：更新本机通达信 vipdoc 到当日收盘，确认股票 / ETF 的 .day 末条日期是今天（本机口径到 2026-11-06）。
  2. 打开 /data 页 →「同步与获取」区块 → 找到「盘后管道」→ 点「立即运行」。
  3. 不想点按钮就用接口：POST /api/pipeline/run 会返回一个 job_id，再用 GET /api/pipeline/jobs/{job_id} 反复看到状态变成 succeeded 为止。

按 上游说明 features.md「盘后定时管道」：系统本来默认 15:35 CST 由 APScheduler 自动跑「拉日 K → 重算 enriched 表 → 跑监控规则」；本机因为是本地数据源，实际节奏是关市后手动 / 脚本触发，建议放在 15:05~15:30。

②点了会发生什么

后台按固定顺序做一整套事，你不用逐项操作：

  • 拉日 K、按除权因子前复权、重算 enriched Parquet 指标表（均线 / MACD / RSI / KDJ / ATR / 量比 / 涨跌停判定 / 连板数等，指标在读取时现算并带进程内快照缓存）——上游说明 features.md「指标流水线」。
  • 先更新本地概念 / 行业 / 地区 / 风格等扩展表，把同一份本地板块归属写进「扩展概念」「扩展行业」表（本机说明 README.local.md「数据」）。
  • 重算市场环境 regime，并在 regime 步骤后追加主线增量（复用 pipeline_regime_enabled 开关，软失败不阻塞）——上游说明 market-phase.md「API 与运行」。
  • 本机补丁会自动收尾：etf_universe_converge.py 把 ETF 最近分区收敛回 52 只策略池口径；pipeline_etf_adj_tolerance.py 只对「ETF 复权因子缺失」这一条 SourceUnavailable 降级（否则任务会误报 failed）；live_flush_sparse_guard.py 防止稀疏实时快照把整日分区覆写成 1 行。

自选股与按需补齐（只补我关心的那几只）

未验证
目标：把自己常看的股票 / ETF / 指数放进「自选」，发现哪只缺日 K 就只补那几只，不为了一两只去拉全市场。这是产品负责人最常用、也最容易误以为「数据不全」的一个入口。

①点哪里（页面与按钮）

  1. 打开 /watchlist 自选页 → 添加标的（列表 / 分组卡片切换、建组改色排序、批量导入）。
  2. 批量导入支持截图 OCR、CSV / TXT、粘贴代码（本机说明 docs/TSP全量操作手册.html §3.1 路由地图）。
  3. 当某只标的显示缺数提示时，点提示里的「补齐 / 重试」。提示分三态：补齐中 / 待配置 / 待数据，悬停可看失败或空返回原因。
  4. 缺日 K 的路由在 /settings?tab=data-sources「数据源」里配（本机须指向 local_quant，见 §15-5）。

②点了会发生什么

按 上游说明 features.md「⭐ 自选与按需补齐」：自选列表读的是共享行情快照；发现缺日 K 时，前端单独提交按需补齐请求，仅补所选标的，不会打开全市场 ETF 同步。补齐复用「设置 → 数据源」里的日 K / 复权因子路由，校验成功后写回原有资产目录，列表、详情和下次启动共用同一份数据。

  • 多人 / 多窗口补同一标的、相同窗口时复用后台执行并受共享容量限制，失败有短暂冷却；补齐完成走 SSE 通知各窗口，另有 30 秒只读版本查询校准漏事件（此通知独立于实时行情开关）。

  • 价格精度：ETF 三位小数、股票两位；开高低收、均线、价格轴、涨跌停价沿用同一精度；涨跌停优先用数据源给的价格，缺失时按 ETF 0.001 元 / 股票 0.01 元取整（features.md）。
