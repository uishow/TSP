二、根因与数据链路

2.1 为什么「日线基础数据」只有一年

  1. TSP 不直接读 TDX 二进制，而是把行情标准化后独立存放在 data-local/kline_daily/date=YYYY-MM-DD/（parquet 分区）+ DuckDB 视图。
  2. 原有 245 个交易日分区，范围 2025-11-04 ~ 2026-11-06；备份里也只有 2026-11-04 单日分区。
  3. 回测请求的 datasets.daily_base.start 被这个物理边界夹住，所以选 2024 也只显示一年。
  4. 该边界来自 scripts/repair_start_boundary.py 打的历史导入标记，不是取不到数。

2.2 数据是怎么进来的

1
回填脚本在容器内运行，用 /app/.venv/bin/python，且 TSP_SOURCE_POLICY=0。
2
preferences.get_daily_data_provider() == "local_quant" → sync_and_persist_daily_batch 走自定义源，不走 tickflow。
3
plugins/local_quant/provider.py 是 HTTP 客户端，POST 到宿主 bridge http://host.docker.internal:7818/query?dataset=daily。
4
bridge → bridge/local_store.py:LocalStore.daily() → 合并 free-stockdb（LGDB 127.0.0.1:7899 / pybao SDK）与 TDX 本地 vipdoc/*.day 二进制。
5
结果写回 kline_daily 新分区，并 refresh_view 刷新 DuckDB 视图（每月一次）。
链路依赖：宿主 free-stockdb LGDB 服务 :7899 必须保持运行，容器不能重启（重启会杀掉后台回填进程；但脚本幂等，重启后重跑会自动跳过已完成月份）。

四、脚本与参数

4.1 路径

用途路径

4.2 参数

参数默认说明
--start2024-01-01回填起点（本次用 2000-01-01）
--end2025-10-31对齐月末，保证全为整月；现有数据自 2025-11-04 起
--dry-runoff只打印计划，不写数据
--no-backupoff跳过写入前全量备份（收尾/补缺口时用）
--skip-finalizeoff跳过 adj_factor + run_pipeline；回填阶段用它
--forceoff忽略整月幂等跳过，强制处理。仅用于补边界缺口，用前须确认目标分区不存在，否则重复 append 会翻倍

4.3 关键设计

  1. 逆序（默认）：最新月份在前，先补齐用户最关心的 2024~2025，旧历史后台依次补齐。
  2. 整月幂等：按 date=YYYY-MM- 前缀判断，已填则跳过，可随时中断续跑、绝不重复写。
  3. 只新增不覆盖：不碰现有 2025-11-04+ 分区。
  4. 收尾解耦：全量指标重算单独跑，避免脚本长尾卡住、便于观测内存。

五、执行时间线与踩坑（本轮真实记录）

#问题症状 / 原因 / 解法
1容器 python 入口系统 /usr/local/bin/python3 缺 pydantic；裸 python 被 overrides/sitecustomize.py 策略拒绝启动。解法：用 /app/.venv/bin/python 且带 TSP_SOURCE_POLICY=0
2tickflow 被遮蔽脚本最初 sys.path.insert(0,'/app/app')，使内部 app/tickflow 遮蔽外部 PyPI 库，报 ImportError: AsyncTickFlow。解法：删除该行
3幂等判断 bug原按 date=每月1号 判断存在，但交易日分区是 2000-01-04 起，导致已填月份被判未填、重复追加。解法：改为按 date=YYYY-MM- 前缀判断
4docker exec 不脱离 + 野进程首次用 nohup ... & 启动，宿主 shell 退出后进程被杀，但已写出部分 2000-02 分区；随后多次 docker exec -d 造成多个 python 并发，写出 2000-03 等不一致分区。解法：docker top 确认唯一进程、docker restart tsp-local 清干净、删掉全部 2000 分区回到 245 原始态，再只启动一次
5春节休市误判2000-02 只有 12 个交易日，一度误以为残缺被中断。实为完整：2000 年春节 2/1–2/11 休市、2/14 开市。同理 2025-10 从 10-09 开始是国庆休市
6正序太慢 / 边界月误跳正序要 40 小时才写到 2024；改逆序后 2025-11 又因已有 11-04+ 分区被整月跳过，补不上 11-01~03。解法：--end 对齐月末 2025-10-31 消除边界月，缺口留给收尾用 --force 单独补
7enriched 孤儿分区灰度 run_pipeline() 曾把 2000-01 写进 kline_daily_enriched；删基础表分区后 enriched 残留 19 个，造成「有指标无基础」。解法：已删除这 19 个分区，四表恢复一致
8status 暂态重启后 /api/data/status 短暂 stats_pending=true / rows:0。是统计重建，不是数据丢失；核验改用 DuckDB 直查
9stdout 缓冲重定向到日志时 Python 缓冲导致「看起来卡住」。解法：PYTHONUNBUFFERED=1 + python -u，进度实时可见
1011-08 39.8 万小文件 → 启动循环全量完成后容器 Restarts 涨到 15、/health 000、日志停在 DuckDB view kline_daily。上游按月流式写 part-stream-N.parquet 累积 398,514 个文件，启动注册视图要展开全部 schema。解法：compact_kline_daily_partitions.py 合并为 6504 个单文件
