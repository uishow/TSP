板块曲线重合 / 大单监控显示「ELTDX 离线」· 排障验收

2026-11-10 12:00–12:25（午休窗口）· TSP v0.3.34 · 容器 tsp-local

用户原话：「板块有了数据实时了，但只显示一条主线呢？」「大单监控显示 eltdx 离线了呢？」

结论速览（大白话）

问题 1「只有一条主线」：不是画图的毛病，是数据只记到了一只股票。今天上午 09:32–11:29，每一分钟里系统只记下了「金杯汽车 600609.SH」这一只票的价格（共 118 根）。板块涨幅是「把板块里所有股票的涨幅平均一下」，每格只有这一只票，于是 9 个板块算出来全一样，9 条线完全叠在一起，看上去就成了一条主线。

问题 2「ELTDX 离线」：那行字说的不是行情源。它其实是「大单监控的独立数据小服务（3021 端口）没连上」。按你第 6 项定的规矩（主网页开着 + 交易时段才启动），午休它会自动关掉，页面就把「关掉了」写成了「ELTDX 离线」，属于文案误导。已经改掉。

但要如实说一句：12:20 复测发现行情源本身也确实又断了（连续 3 次 /query realtime 都是 HTTP 503 / eltdx 超时）。所以你看到「离线」时，一半是标签写错，一半是行情源真的不稳。12:07 曾短暂恢复过（拿到 5613 行全市场快照），之后又断，属于间歇性。

三态：根因定位 已端到端实测；文案修复 已端到端实测；「上午历史分钟 K 补回、板块曲线真正分开」未验证 / 被行情源阻塞。

① 板块为什么只显示一条主线

你看到什么 → 实际发生了什么

页面上 9 个板块的走势曲线几乎完全重合，涨幅数字也一样。接口 /api/sector-rotation 里 sectors[].n_members_with_bars 全是 1——意思是「这个板块本来有几十到几百只成员股，但今天这一格只找到 1 只票有价格」。

那 118 根 K 是哪来的

是上游「单只股票分时页」被打开时单独补拉并落盘的真实分钟 K（source=null、OHLC 各不相同、成交量金额真实）。它不是全市场同步，所以只覆盖一只票。/api/kline/minute-batch 的实现注释也写明「补拉并落盘，取到即写」——这正好给了我们一条补数据的正规通道。

能不能把上午补回来

能，而且已实测证明补进去确实会让曲线分开。12:10 用上游原生批量接口成功补了 20 只股票各 120 根真实 K（5.95 秒 / 525 KB）。补完后：分区从 5,608 → 7,869 行，n_members_with_bars 从 1 出现 2，timeline 末尾 leader_pct 0.0498 与 market_pct 0.0001 首次出现差异，曲线开始不再完全重合。

但全量补没能跑完：随后 50 只 / 200 只批量均返回 eltdx request failed (ResponseTimeoutError)；连续 3 批 20 只也全部 6.3 秒超时；完整实跑新脚本 --limit 20 得到 HTTP 502。结论：eltdx 的「分钟协议」通道目前基本不通，只有「实时快照」通道偶尔能通。上午那段历史价格当时没有被记录下来，不能凭空编——项目铁律是不伪造数据。

顺带清理了这次测试带进来的 19 根「13:00」未来占位柱（午休时上游注入的），as_of 从虚假的 13:00 回到真实的 11:25。已备份 runtime/kline_minute_20261110.bak.121500.parquet。

给你的一眼判断法

打开 http://127.0.0.1:3018/api/sector-rotation?auto_rows=9&sort_by=score，看 n_members_with_bars：如果是 1，页面那条线就是「一只票假扮的全市场」；涨到几十、几百才是真数据。

② 大单监控为什么显示「ELTDX 离线」

标签真正检测的东西

扩展页 data-local/ext_pages/big_order/bundle.js 里，setBadge(false, "ELTDX 离线") 出现在 refreshFlow() 的 catch 分支——也就是请求 http://127.0.0.1:3021/bigorder/flow 失败的时候。它检测的是「3021 这个独立数据小服务连没连上」，跟 eltdx 行情源没有任何关系。合格时显示「ELTDX 在线」同样不准确。

3021 为什么没开

检查项实测值
看门狗 runtime/bigorder_watchdog.json @12:20trading=false / 非交易时段 12:20、page_open=true（Google 浏览器连着主站）、want_running=false、service_running=false
curl :3021/health000（没在跑）
规则出处你第 6 项指令「TSP 主网页打开且在交易时段则启动，其他则关闭」，看门狗判定 9:15–11:35 / 12:55–15:10 为交易时段

所以午休 3021 被关掉是符合你定的规矩的正确行为，不是故障。13:00 前它会自动回来。

改了什么

  • 在线文案：ELTDX 在线 → 数据服务 在线。
  • 失败文案按交易时段区分：交易时段显示 数据服务未启动（非行情源故障）；非交易时段显示 非交易时段 · 数据服务按规则暂停。判断口径与看门狗完全一致（周一到周五 9:15–11:35 / 12:55–15:10）。
  • 头部注释从「ELTDX 适配器」改为「大单监控数据服务」，并注明状态标签不代表行情源状态。
  • 数据口径零改动：逐笔方向、金额公式、阈值、四档汇总、双源只比方向等一律没动，只改了状态文字和注释。

想午休也看大单数据怎么办

看门狗本来就留了强制开关：启动看门狗时带 TSP_BIGORDER_FORCE=1 就会让 3021 常开（不分辨交易时段）。本轮没有替你改这个规则，因为「交易时段才开」是你自己拍板的。

④ 三步操作（点哪里 → 发生什么 → 结果在哪看 → 出错怎么查）

第 1 步 · 先把行情源接回来（需要你自己的终端，不要经过 AI 沙盒）

在项目目录执行：.venv/bin/python scripts/manage.py stop && .venv/bin/python scripts/manage.py start

发生什么：宿主桥接重建 eltdx 热连接池。结果在哪看：curl --noproxy '*' -X POST http://127.0.0.1:7818/query -H 'Content-Type: application/json' -d '{"dataset":"realtime","symbols":[]}' 应返回 200 且 5,000+ 行。出错怎么查：仍是 503 / 0 行 = 7709 裸协议被网络层拒绝（11:16 已用 7 项排除法定性），需检查网络策略，不是代码问题。

第 2 步 · 先小范围试补，通了再补全部

.venv/bin/python scripts/backfill_minute_today.py --limit 200 → 确认打印「补回 200 只」后，再跑 .venv/bin/python scripts/backfill_minute_today.py

发生什么：每批 20 只调用主站自带批量接口，上游把真实分钟 K 写进当日分区；已有 ≥100 根的自动跳过；失败自动重试后跳过。结果在哪看：脚本末尾「分区每时间点行数 中位=xxxx」；再看板块接口 n_members_with_bars 是否从 1 涨到几十、几百，pct_now 不再全部相同。出错怎么查：打印 eltdx / Timeout / 502 = 行情源分钟通道仍不通，等恢复重跑即可，脚本不会写任何假数据。

第 3 步 · 刷新页面看结果

浏览器打开板块轮动页，Cmd/Ctrl+R 刷新；大单监控页同样刷新一次看新状态文字。结果在哪看：走势图从 09:31 到收盘应有多条分开的线；午休时大单监控应显示「非交易时段 · 数据服务按规则暂停」而不是「ELTDX 离线」。出错怎么查：若曲线仍重合，回到第 2 步的输出看「补回 X 只」是不是 0。

时间提醒：收盘后跑补齐脚本成功率最高（行情源连接稳定、不影响盘中）。若 13:00 开盘前没跑完，建议先让下午实时数据正常写入，收盘后再补上午。

⑥ 升级兼容与回滚

  • 升级兼容：本轮改动全在挂载卷 data-local/、scripts/、runtime/，不碰镜像随版本分发的文件。TSP 升级后主功能照常，最坏是 /api/kline/minute-batch 接口变更导致补齐脚本失效（脚本只影响补数，不阻断启动、不影响页面）。扩展页文案随 data-local/ 挂载保留，不随镜像覆盖。
  • 回滚文案：把 runtime/big_order_bundle.bak.121500.js 和 big_order_page.bak.121500.json 拷回 data-local/ext_pages/big_order/，刷新一次页面即可（55,053 B / f1c13dca…b51c881）。
  • 回滚数据：把 runtime/kline_minute_20261110.bak.121500.parquet（清理未来柱之前）或 .bak.115637.parquet（最原始 5,608 行）拷回 data-local/kline_minute/date=2026-11-10/part.parquet，再 POST /api/kline/refresh_views。
  • 一键开关：看门狗 TSP_BIGORDER_FORCE=1 强制 3021 常开；快照补丁 TSP_LOCAL_QUANT_SNAPSHOT_MINUTE=0 回退旧逐批取数；后台挖掘 TSP_MINING_BG=0。
