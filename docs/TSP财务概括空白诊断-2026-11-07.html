一、现象（用户截图）

用户截图：页面在 127.0.0.1:3018/financials（直连 3018，非 3081）。「财务概况」页个股区：中联重科 000157.SZ，报告期 2026-09-30。

「核心指标」卡片：基本每股收益 / 稀释每股收益 / ROE / 毛利率 / 净利率 / 资产负债率 / 营收同比 / 净利同比 全部显示 –，仅「每股净资产 BPS = 6.72」有数。顶部状态卡（核心指标 4万、利润表 4万…5480 只标的）均正常 —— 说明接口与网络是通的。

结论反转：本问题不是 3081 转发/代理（此前回测选择器空白的假设），而是本地财务数据集本身残缺 / 字段名错位。前版文档据此已纠正。

二、为什么排除网络/3081

  • 截图里 Network 面板显示 status → /api/intraday/status 返回 200 OK；财务状态卡（4万行/5480 标的）由 /api/financials/status 正常填充。
  • 前端静态壳 + 状态数据都加载成功，唯独「核心指标」明细值空缺 → 是数据内容问题，不是取数失败。

四、根因（两类缺陷）

缺陷 A — 字段名错位（EPS 必现）：UI 卡片读 eps_basic，但本地 metrics 表只写了 eps_observation（eps_basic 为 null）。BPS 因 bps 列恰好有值而正常。属数据/前端 schema 不一致。

缺陷 B — 衍生指标未计算（ROE/毛利率/净利率/资产负债率/同比 全空）：metrics 表这些列全部为 null，因本地财务同步未计算衍生比率（field_mapping_verified:false）。但原始利润表/资产负债表字段齐全，ROE、净利率、资产负债率可由原始数据算出；毛利率需 gross_profit（原始为 null，可由 revenue−operating_cost 推算，需谨慎）；同比需去年同期。

五、范围

仅静态核查 + 抽样实测 抽样 001219.SZ 同样 roe/gross_margin/net_margin 全 null → 判定为系统性（影响全部 ~5490 标的），非个别股票。即「财务概况 / 核心指标」在所有股票上都会大面积显示 –。

六、修复方案（已定：运行时换算，不动数据源）

你的决策：「不要改动本地数据源，采用换算的方式填充数据。」 因此放弃任何对 data-local 财务 parquet 的回写，改为读取时运行时换算。落地方式：TSP override 机制（overrides/bootstrap.py 在 uvicorn 启动时装载），包装 financials 模块全局 get_financial_df，仅当 table=="metrics" 时在返回前由原始 income/balance 表换算补全；原始 parquet 一个字节都不改。

缺陷换算口径覆盖
缺陷 A（EPS 字段名错位）eps_basic ← eps_observation（当 eps_basic 为 null）；eps_diluted ← eps_diluted_observation已覆盖
缺陷 B（衍生比率未算）roe=归母净利/净资产、roa=归母净利/总资产、net_margin=归母净利/营收、debt_to_asset_ratio=负债/总资产、revenue_yoy / net_income_yoy（去年同期同 fiscal_period 同比）已覆盖
缺陷 B 残留（毛利率）原始表无 gross_profit 字段，不强行推算保持 –（与官方口径一致，非缺陷）

新增文件 overrides/financials_metrics_enrich.py（约 200 行），在 overrides/bootstrap.py 末尾 install() 装载。换算口径为本地推算，可能与官方算法有细微差异；仅填充原本为 null 的字段，不覆盖任何已有值。
