3主要解决什么问题（产品视角）

3.1 原来卡在哪里

  1. 策略「看起来丢了」：回测页默认按「股票」拉策略列表，七星175 这类 ETF 策略被服务端过滤掉，页面上根本看不到；你会以为策略没加载 / 加载失败，实际是筛选条件把它藏了。
  2. 切换入口还藏得很深：「资产类型 [股票] [ETF]」不在主界面，而在「右上角高级设置 → 回测范围」tab 里，默认 tab 是「策略条件」，很多人不知道要切。
  3. 来回切还倒霉：原版每点一次切换按钮，都会把已选策略和已填股票池清空（d(null), j("")），选好的东西要重填；切错口径还会报「策略不支持 asset_type 'stock'」或读到错误的行情表。

3.2 一句话说清它解决什么

把「策略列表能不能同时看到」和「这一笔回测用哪张行情表」这两件事拆开： 列表里股票策略和 ETF 策略同时可见、随手可选；真正跑回测时，口径自动跟随你选的那条策略（选七星175 就是 ETF，选股票策略就是股票），不用人去记、去切、去猜。 结果是：策略不再"失踪"，也不用为了换一类策略反复切开关；同时保证回测读的仍然是正确的数据表，结果不串味。

3.3 顺手修掉的三个小坑

  • 点按钮不再清空已选策略与股票池；两个按钮可同时高亮。
  • 策略列表还没加载完时禁止点「运行」，避免空跑一次。
  • 提示文案改成「可同时选股票+ETF；回测口径自动跟随所选策略」，把规则写在界面上。

3.4 更关键的一层价值：不影响版本升级

你两次强调「所有二开不能影响 TSP 自身版本升级」。这个功能本身就是按这条铁律做的，而且今天真实升级时被验证过： v0.3.34 换掉了前端文件名与内部变量名，补丁没有白屏、没有阻断启动，只是暂时失效并明确记日志；随后在挂载卷里改一下映射、重启即恢复。 也就是说，它解决的不只是「能不能都选」，还包括「以后升级时这个定制不会变成升级的阻碍」。

4根因、解法与边界

层次内容
根因（前端）资产类型是一个单字符串变量（v0.3.31 叫 C，v0.3.34 叫 $），被 12 处引用：既决定策略列表请求 /api/strategies?asset_type=…，也决定回测请求、指标状态、股票池候选、按钮高亮。
根因（后端）app/api/strategy.py::list_strategies() 用 asset_type 过滤 META.asset_types；?asset_type=stock,etf / all 都返回 0 条。
硬约束一次回测只能一种资产口径：asset_type 是单值，股票 / ETF 两张行情表分开，矩阵 profile 按口径构建，分钟策略仅股票。所以不能做「一次回测同时跑股票+ETF」的混合回测（评估里的方案 3 已否决）。
解法额外引入 __tspVisible（只管列表可见性）与 __tspEffectiveAsset（只管回测生效口径）两个变量：列表请求在双选时不传 asset_type（服务端返回并集 3 条）；选中策略后从 asset_types 推导口径，服务端仍收合法单值。后端零改动、证据链不变。
能力边界（别误解）：「都选上」= 两类策略都能在列表里看到并任选一条；不等于一笔回测同时用股票和 ETF 两个池子。选中哪条策略，就按那条策略声明的口径跑。

5点哪里 → 发生什么 → 结果在哪看 → 出错怎么查

  1. 点哪里：回测页 → 右上角「高级设置」→ 切到「回测范围」tab → 「资产类型 [股票] [ETF]」。现在两个按钮可同时高亮（默认就是两个都选）。
  2. 发生什么：下方策略列表一次性显示 3 条（含七星175 ETF 策略）；点其中任意一条，回测口径自动按该策略的 META.asset_types 设定；点「运行」发起 SSE 回测。
  3. 结果在哪看：页面的净值曲线 / 交易明细；证据链落盘在 data-local/backtest_runs/{run_id}.json，里面 config.asset_type 与 lookahead/execution_timing 可直接核对。
  4. 出错怎么查： 
    docker logs tsp-local 2>&1 | grep MULTI_ASSET_PATCH
# ACTIVE  = 定制生效；SKIPPED = 上游又换了 chunk，页面回官方二选一但功能正常
# DISABLED = 被一键开关关掉了
curl -s http://127.0.0.1:3018/api/strategies | python3 -m json.tool   # 期望 3 条、load_errors=[]
  5. 要临时关掉：touch overrides/multi_asset_patch.disabled && docker compose restart，或设 TSP_MULTI_ASSET_PATCH=0；不碰 compose digest / 镜像。
