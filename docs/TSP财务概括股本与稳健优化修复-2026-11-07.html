一、现象（用户二次反馈）

在「财务概括」核心指标修复上线后，用户继续反馈两点：

  • ① 财务概括中「股本」也无数据展示：财务页「股本」Tab（总股本 / 流通股本）整列空白。
  • ② 回测 → 验证 → 稳健优化，第4、5步没法操作：第4步提示「请至少勾选一个参数」，第5步「▷ 开始稳健优化」按钮被拦截无法点击（用户附带截图，红框标注报错与按钮）。

两点均为前端取数/配置层问题，并非网络或 3081（本机唯一实例 3018 直连正常）。

二、股本空白：根因

已端到端实测 财务页「股本」Tab 前端配置：

shares:[{label:"总股本", fmt:"amount", key:"total_shares"},
         {label:"流通股本", fmt:"amount", key:"float_shares"}]

即它读 /api/financials/shares 的 total_shares 与 float_shares。实测该表（以 000157.SZ 为例，8 期）：

字段2026-09-30（最新期）更早各期结论
total_shares（总股本）86.49亿（有值）全部 null仅最新期有值，其余 –

三、股本空白：修复 + 实测

已端到端实测 沿用既有 override（不改数据源、运行时换算）：扩展 overrides/financials_metrics_enrich.py，在 _wrapped 中当 table=="shares" 时调用新增的 _enrich_shares：

def _enrich_shares(df):
    # 仅当 float_shares 缺失且 circulating_shares 有值时, 补 float_shares ← circulating_shares
    for r in df.to_dicts():
        if r.get("float_shares") is None:
            r["float_shares"] = r.get("circulating_shares")

沿用 overrides/bootstrap.py 入口装载，容器重启生效；原始 parquet 一字不改。

实测（2026-11-07 15:07 重启后）：GET /api/financials/shares?symbol=000157.SZ 2026-09-30 → total_shares=86.49亿、float_shares=70.70亿（= circulating_shares）。更早各期仍 –（源数据本就无，如实呈现）。启动日志：FINANCIALS_METRICS_ENRICH: installed (runtime conversion of core metrics + share capital)。

UI 验收：浏览器硬刷新 127.0.0.1:3018/financials → 选股 → 切到「股本」Tab，确认最新期 总股本 / 流通股本 已有数；更早报告期显示 – 属数据真实缺失，非缺陷。

四、稳健优化卡阻：根因

已端到端实测 前端稳健优化按所选策略 meta["params"] 渲染「可勾选的参数组」，计数 n；当 n===0 时显示「请至少勾选一个参数」并禁用「开始稳健优化」。

用户所选策略为 custom_simple_ma_cross（演示·均线交叉(5/20)）。其 compute_signals 已读 fast_period/slow_period，但 META 未声明 params → 后端 GET /api/strategies 返回 params:null → 前端无参数组可勾选 → 卡阻。

对比：另一自定义策略 custom_qx175_etf_rotation 的 META 已自带 params（lookback_days 等），稳健优化在该策略上正常。故这是「均线交叉(5/20)」策略本身的缺陷，非平台 bug。

后端校验逻辑（app/backtest/optimizer._grid_candidates）：要求 param_grid 的每个 pid 必须存在于 strategy.meta["params"]，否则报「参数 'x' 在该策略中不存在」。因此只要把 fast_period/slow_period 补进 META，前端出现勾选项、后端亦接受该网格。

五、稳健优化卡阻：修复 + 实测

已端到端实测 给 data-local/strategies/custom/custom_simple_ma_cross.py 的 META 增加（schema 对齐 app/backtest/optimizer 与策略提示词示例）：

"params": [
  {"id":"fast_period","label":"快线周期(天)","type":"int","default":5,"min":3,"max":20,"step":1},
  {"id":"slow_period","label":"慢线周期(天)","type":"int","default":20,"min":10,"max":60,"step":5},
]

POST /api/strategies/reload 后，GET /api/strategies?timeframe=1d 对该策略返回：

params: [{fast_period...},{slow_period...}]
params_defaults: {"fast_period":5,"slow_period":20}

实测（真实跑一轮稳健优化）：GET /api/backtest/optimize-robust/stream 带 param_grid={"fast_period":[5],"slow_period":[20]}、symbols=3只ETF、短窗口 → SSE 依次返回 event: job → event: done，无任何「参数不存在」等错误，证明后端接受新网格并跑完。前端参数组复选框现已出现，第4/5步可正常操作。
