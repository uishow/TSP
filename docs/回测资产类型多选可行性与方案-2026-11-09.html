一、一句话结论

能让两类策略同时出现在列表里，而且接口层已经天然支持——/api/strategies 不传 asset_type 就返回全部 3 条（股票 1 + ETF 2），实测通过。
但有一个必须先说清的边界：后端一次回测只能用一种资产口径——asset_type 是单个字符串，决定读 kline_daily 还是 kline_etf_daily，还要按类型中和基础过滤条件。所以「两者都选」只能作用于策略列表的可见性，不可能让一次回测同时跑股票和 ETF 的组合。
由此推出一条必要配套规则：选中某个策略后，回测口径要自动跟随该策略自己的 META.asset_types，否则会出现「按股票表跑 ETF 策略」的错配或 no matrix-native cache profile 报错。
本轮零改动：只做可行性核查、出评估文档与工作日志，没有改前端、后端、配置或行情数据，没有重启服务。第四节给出三个方案，等你选定范围后我再实施。

所以「把单选改成多选」不是改一个按钮那么简单：如果直接把 C 变成 "stock,etf" 或数组，那 3 个 C==="etf" 判断会全部落到 stock 分支，回测请求也会把非法值传给后端。正确做法是把「列表可见性」和「本次回测生效口径」拆成两个变量。

三、硬约束：为什么「一次回测混合两类资产」不可行

约束点源码 / 实测依据
请求模型是单值upstream/app/api/strategy.py:251-257 RunRequest.asset_type: str = "stock"；app/api/backtest.py:663 SSE 端点 asset_type: str = "stock"。传 stock,etf 不会被解析成两个。
行情表是分开的股票日线 kline_daily（6504 交易日 / 1648 万行）与 ETF kline_etf_daily（1658 交易日）是独立 parquet 分区；repo 按 asset_type 选表。实测：ETF 最早 2020-01-02，股票最早 2000-01-04，混跑连区间都对不齐。
基础过滤要按类型中和app/backtest/strategy.py:590-606 _basic_filter_for_asset()：非股票资产没有股本数据，会把市值 / 流通市值 / 换手率 / 价格界 / 板块过滤一律置 None，否则候选被静默清零。这个动作是「全量单选」的，没有逐标的类型概念。
矩阵缓存按类型构建:392-425 构建 matrix_native 缓存 profile 时 if asset_type not in strategy.meta.get("asset_types",["stock"]): continue，全部跳过就抛 ValueError("no matrix-native cache profile available for asset_type=...")。
分钟策略只支持股票:78-95 与 :2159：if config.asset_type != "stock": return _err("分钟策略回测当前仅支持 A 股 (stock)")。
结论：要做到「一次回测里同时持有股票和 ETF」，需要重新定义标的池、估值字段、复权口径、证据链与缓存 profile，属于后端架构改造，不是 UI 开关问题。本项目当前不建议走这条路。
好消息：你要解决的是「选了股票就看不到 ETF 策略」——这纯粹是列表可见性问题，不需要碰上面任何一条约束。只要让列表取并集，再让回测口径自动跟随所选策略即可。

四、三个方案对比（请你选一个）

方案做什么 / 达到什么效果改动面取舍
方案 1
后端优先
（推荐）		 ① /api/strategies 不再按 asset_type 硬过滤 → 无论开关停在哪，下拉里股票 + ETF 策略全部出现；② 回测端点按 strategy_id 的 META.asset_types 自动纠正 asset_type 并写进 config / 证据链 → 点 ETF 策略就按 ETF 表跑，不会错配。零前端改动。 新增 1 个 overrides/ patch 模块 + bootstrap.py 注册一行；需重启容器。 最稳、完全可回滚、可端到端实测。缺点：两个按钮看起来仍是互斥高亮（但它已不再过滤策略），需要改一句提示文案说明新语义（单字符串替换，风险极低）。
方案 2
完整 UI 多选		 方案 1 的全部能力 + 把「股票 / ETF」两个按钮改成可同时勾选的复选框（两者都亮 = 显示并集；只亮一个 = 只看该类），并让「生效口径」跟随所选策略。视觉上真正「两者都选上」。 方案 1 + 运行时注入前端补丁：对压缩 JS 做 4~6 处精确字符串替换（列表请求、回测请求、三个 C==="etf"、按钮 JSX、缓存恢复）。需重启 + 浏览器验证。 体验最贴合你的描述，但要改镜像里的压缩构建产物，维护成本与白屏风险更高；本项目已有用户反馈过「不稳定」，建议先做方案 1 验证语义，再决定要不要上 UI。
方案 3
混合资产回测		 一次回测真的同时跑股票 + ETF 两类资产。 后端架构改造：合并两张行情表、逐标的类型标记、复权/估值字段重定义、证据链与缓存 profile 重写。 不建议：工程量大、会动到已验收的回测证据链，且当前 ETF 未前复权、七星175 有静态池前视偏差，混合结果的业绩语义更不可靠。
我的建议：先做方案 1。它用最小改动解决「看不到 ETF 策略」这个真实痛点，且把「自动跟随策略口径」这条安全规则做实；确认好用后，如果仍想要两个按钮同时亮，再叠加方案 2 的 UI 改造。

六、改造后页面怎么点 / 结果在哪看 / 出错怎么查

① 找策略
点哪里：回测页左侧「策略设置」→ 策略下拉框。
会发生什么：股票策略（520 金叉）与 ETF 策略（七星175、演示均线交叉）同时在列表里，不用再去高级设置抽屉切「回测范围」。
结果在哪看：下拉列表项本身；分组按钮保持「全部 / 自定义 / AI」，别停在「AI」（会过滤掉两个 source=custom 的 ETF 策略）。
出错怎么查：若仍只有 1 条，先开 /api/strategies?asset_type=stock 看返回条数；应 ≥3。若为 0 或 500，说明 patch 没装载，查容器启动日志的 BACKTEST_ASSET_SCOPE_ACTIVE。
② 运行回测
点哪里：选中任一策略 → 设好区间 → 点「运行回测」。
会发生什么：系统按该策略自己的资产类型取数（ETF 策略读 ETF enriched，股票策略读股票日线），开关停在哪个都不影响口径。
结果在哪看：结果页「本次数据范围」与证据链 data-local/backtest_runs/{run_id}.json 的 config.asset_type。
出错怎么查：若报 no matrix-native cache profile available for asset_type=... 或「未产生买入信号」，先看证据链里 asset_type 是否与策略一致；ETF 起点不要早于 2020-01-02。
③ 两个开关还有没有用
方案 1 下它们不再过滤策略，只影响股票池输入的候选口径与「指标数据」提示。默认股票池为空（全市场筛选），所以大多数场景无需切换；单票调试 ETF 时手动切到 ETF 即可。实施后需实测确认

七、风险与回滚

风险说明 / 缓解
静默改口径自动纠正 asset_type 会改变请求语义。缓解：必须写 BACKTEST_ASSET_TYPE_COERCED 日志并让纠正后的值进入 job_key / config / 证据链，绝不只在内存里改。
缓存串味job_key 已包含 asset_type（app/api/backtest.py:620-637），纠正后的值参与哈希，不会命中错误缓存。实施时需实测两次不同策略的 run_id 不同。
压缩 JS 白屏只有方案 2 会动前端。缓解：先做方案 1 验证；若上方案 2，必须逐处字符串替换 + JS 语法检查 + 浏览器冒烟，并保留原版一键还原。
容器重建丢改动/app/static 不在挂载卷。缓解：补丁模块放 overrides/（已挂载），由 bootstrap.py 每次启动注入；不要直接改容器内文件了事。
策略池前视偏差既有事实：七星175 静态池、ETF 未前复权、lookahead.sampled=True。本改造不改变这些限制，长历史结果仍不能当真实业绩。
回滚：方案 1 只需删掉 bootstrap.py 里那一行 attach 调用并重启容器，数据零改动、无需恢复备份；方案 2 额外还原静态资源覆盖即可。
