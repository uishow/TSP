5. 唯一会失效的定制：前端「股票 + ETF 同时选」

这个补丁（overrides/multi_asset_patch.py）是靠在压缩后的前端代码里做精确文本替换实现的，一共两套 profile（分别针对 v0.3.31 与 v0.3.34 的分块）。我把两套 profile 的锚点全部拿出来，逐条在新旧分块里做了命中测试：

Profile针对版本在 v0.3.34 分块命中在 v0.3.35 分块命中结论
_REPLACEMENTS_V031v0.3.312 / 111 / 11早已不用于当前版本
_REPLACEMENTS_V034v0.3.3411 / 11 ✅2 / 11升级后会 MULTI_ASSET_PATCH_SKIPPED
影响范围（说清楚，不夸大）：只有回测页那个「可同时选股票 + ETF」的多选开关会消失，回到上游原生的「单选股票 / 单选 ETF」。 回测本身、策略、筛选、大单监控、扩展页全都不受影响。
要恢复的话：我按 v0.3.35 的新分块再写一套 _REPLACEMENTS_V035（11 条锚点重新对位），改完同轮验证并保留回滚点。这项工作只在您决定升级之后才做。

为什么两套 profile 会失配：前端是压缩产物，变量名（[C,R] → [$,L] 之类）和内部函数名每次构建都会重新分配。所以补丁只能「认代码形状」而不是「认文件名」。这也是铁律里禁止硬编码带哈希的文件名的原因。

6. 「全市场竞价扫描」补齐了吗 —— 没有

这是之前登记在升级触发条件里的那条：如果新版补齐了，就直接用原生、不用二开。本轮实测结果：

检查点结果
